CURIOLAB BLOG · EXPERIMENT DESIGN

A practical template for comparing AI tools.

A useful comparison starts with one real task and a fair test—not a leaderboard or a single impressive answer. Use this lightweight protocol to compare tools on work you actually need done.

Experiment workflow · Approximately 6 minutes

1. Choose one task with a clear outcome

Pick a task you understand well enough to judge. Examples include summarizing a lecture section, extracting action items from a meeting note, explaining a concept for a beginner, or drafting a short email. Avoid changing the task between tools.

Write down what a successful answer must include before testing. This helps prevent you from changing the rules to favor the output you happen to like.

2. Use matched inputs and instructions

Give each tool the same source material and the same core prompt. Record any differences that cannot be avoided, such as a file-size limit or a feature available only in one product. Do not quietly give one tool more context or extra revision rounds.

i

Copy-ready test prompt: “Complete the task using only the source material below. Preserve important details and conditions. Do not invent missing facts. If the source does not support a claim, label it as uncertain or not provided. Organize the answer for the intended reader. After the answer, list any important ambiguities or limitations.”

Replace “the task” with your exact task and paste the same source material into each tool. Keep the original outputs unchanged in your records.

3. Score against prewritten criteria

Use a simple scale from 1 to 5. Write what each score means before reading the outputs; otherwise, the scoring can drift from one tool to another.

CriterionQuestion to ask
AccuracyAre claims supported, and are errors or invented details present?
CoverageDid it include the required points without important omissions?
ClarityCan the intended reader understand and use the answer?
OrganizationIs information structured in a way that helps the task?
Revision effortHow much work was needed to make the result usable?

Not every task needs equal weights. For source-based study notes, accuracy and coverage may matter more than style. For brainstorming, variety and usefulness may matter more. Choose weights that match the task and publish them with the results.

4. Record time, cost, and constraints

A response that looks good but takes longer to verify may not be the best option. Track how long you spend checking and editing each output, plus any usage limits, paid features, or privacy constraints relevant to your decision.

  • Tool and model/version, if visible
  • Date of test and exact prompt
  • Source material or a reproducible description of it
  • Original output and number of revision rounds
  • Scores, reviewer notes, and editing time
  • Known missing information and test limitations

5. Avoid overstating the conclusion

A small test tells you how tools performed on that task under those conditions. It does not prove that one tool is universally better. If you have one reviewer, say so. If output identities are hidden, do not guess which model produced each answer. If records are incomplete, label the result provisional.

When possible, run more than one task and repeat the comparison. Preserve ties when the evidence does not support a clear winner.

Reusable results table

RecordWhat to write down
TaskOne-sentence task and intended reader
SetupPrompt, source, tools, date, and versions
EvaluationCriterion scores with a short evidence note for each
EffortVerification time, editing time, and revision rounds
LimitationsMissing records, uncertainty, and what the test cannot show

For the longer method, read How to compare AI tools fairly. If the task involves study material, use the source-checking workflow before relying on the generated notes.

✳

CurioLab principle: publish the method and limitations alongside the result. A transparent small test is more useful than a confident ranking with no evidence.
